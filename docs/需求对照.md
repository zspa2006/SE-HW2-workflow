# Homework 2 需求解读与验收对照

来源：工作文件夹原始 `Homework 2.pptx`，共 7 页。第 2–4 页给出本次作业要求；第 5–7 页为课程规划与后续团队项目说明。本次按独立的 Simple Workflow MVP 完成，不把后续六人团队项目混入当前交付。

作者：潘彦博（2404080334）

## 1. 作业要求摘录与项目选择

项目目标：搭建 2–3 个 Agent 协作的简单 Workflow，理解 Workflow 编排、Agent 间通信与状态管理。周期为 2 Weeks。

可选方向包括 Mini SE、代码审查、文档生成、测试流程和内容创作。本项目选择**文档生成流程**，以原有代码解释方向为基础，把单 Agent 扩展成三个角色：代码分析、文档生成、文档审校。

## 2. 必须实现项

| 原始要求 | 具体实现 | 验收方式 |
| --- | --- | --- |
| 至少 2 个 Agent 协作完成完整流程 | 3 个独立角色，分别实现分析、写作和审校策略 | 正常运行，消息依次来自 analyze/write/review |
| Agent 间消息传递或状态共享 | `Result` 结果信封、`messages` 发送接收记录、`artifacts` 共享产物 | 查看 `state.json` 及 HTML 消息表 |
| 基本流程控制，顺序执行 | 路由驱动 `analyze → write → review → END` | 正常演示记录 3 次节点提交 |
| MVP 可运行，无需复杂调度 | Python 3.10+ 标准库 CLI，无需密钥即可演示 | 按 README 首条命令执行 |

## 6. 验收顺序

1. 阅读 README，运行正常演示，确认最终产物存在。
2. 加 `--demo-revision`，确认消息链中出现 review → write，第一轮问题为缺少“验证建议”。
3. 使用 `--stop-after analyze` 暂停，再恢复，确认分析只执行一次。
4. 查看 `docs/evidence` 的同类留存结果，核对消息、行号与接口数量。
5. 执行单元测试，核对测试报告中的限制和跳过项。
6. 查看 Design 的新增 Agent 示例，确认引擎没有硬编码调用三个角色。
