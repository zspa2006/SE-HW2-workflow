## 2. 流程是否完整

正常运行使用 `pricing.py` 和 `orders.py`，分析结果包含 5 个公开定义：两个计价函数、`Order` 类、`Order.payable` 方法和 `summarize` 函数。文档 Agent 根据这些记录生成说明，审校 Agent 检查覆盖和行号，通过后生成 `README.generated.md`。

返修演示通过 `--demo-revision` 主动让初稿少一个章节，用来检查失败分支。第一次审校指出“缺少章节：验证建议”，文档 Agent 修改后第二次通过。每一轮都保存了结果，可以对照 `step-003.json` 和 `step-005.json` 查看。

## 3. Agent 是否有实际协作

分析结果放在 `artifacts.analysis`，文档 Agent 从这里读取数据，而不是重新单独分析一次。草稿放在 `artifacts.draft`，审校同时读取分析和草稿。退回时，问题写入 `artifacts.review`，下一轮文档 Agent 可以读取。

引擎负责保存结果和转发消息，Agent 不能直接修改共享状态。`messages` 中能看到 analyze → write、write → review，以及返修时的 review → write。暂停恢复时，`current` 记录下一节点，已经保存完成的节点不会重复执行。

## 4. 怎么检查扩展性

运行 `python scripts/extend_demo.py`，会在分析和写作之间加入 `AuditAgent`，检查输入文件是否都出现在分析结果中。扩展只增加 Agent 实现、注册项和流程配置，没有修改 `engine.py`。主流程仍保持三个 Agent。

路由中 `review` 的不同结果可以分别指向 END 和 write，说明流程不只是固定顺序调用。新增流程还会检查节点和目标是否有效。
