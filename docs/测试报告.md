## 1. 环境和结果

测试环境为 Windows、Python 3.12.8。执行命令：

```powershell
python -m unittest discover -s tests -v
```

共 42 项测试，41 项通过，1 项跳过，没有失败项，耗时约 6.3 秒。[原始输出](测试原始输出.txt) 保留了逐项结果。

跳过的是符号链接越界测试，因为当前 Windows 环境没有创建符号链接的权限。普通相对路径越界和目录外绝对路径的测试已经通过，符号链接这一项仍需要在有权限的环境中再检查。

## 2. 主要检查内容

| 内容 | 检查方法和结果 |
| --- | --- |
| 完整流程 | 三个 Agent 依次执行，生成文档并通过审校 |
| 返修 | 初稿漏章后被审校发现，返回修改，第二版通过；两版结果均保存 |
| 消息传递 | 检查发送者、接收者及共享产物，确认下游读取上游结果 |
| 暂停恢复 | 分析后暂停，恢复只执行写作和审校，累计节点数仍为 3 |
| 失败恢复 | 写作节点失败后保留分析结果，修正问题后可以继续 |
| 输入变化 | 改动源码后拒绝恢复，运行中改动也不能继续发布文档 |
| 重试和次数限制 | 临时错误重试，永久错误停止，返修上限和 50 步限制有效 |
| 文件读取 | 检查越界、编码、二进制、文件大小、重复输入和总大小限制 |
| 审校规则 | 能发现漏章、漏接口、重复或未知接口，以及错误的源码位置 |
| 新增节点 | 注册 audit 节点并改路由后，可以执行四节点流程 |
| 模型接口 | 本地 HTTP 服务检查请求路径、认证头、响应解析和错误分类 |
| 输出 | 检查 HTML 转义、密钥不写入结果，以及未通过审校时不输出最终文档 |

具体测试函数见 `tests/test_workflow.py` 和 `tests/test_backend.py`。

## 4. 模型部分

模型测试使用本地 HTTP 服务返回约定的 JSON，检查三个角色是否分别请求、下游是否能使用返回结果，以及错误时是否正确重试。目前没有用真实账号连接云端模型，因此还不能根据这些测试判断模型解释的质量。

离线模式没有网络请求，文档说明来自 AST 和源码 docstring。无论使用哪种模式，业务逻辑和说明是否完全正确仍需要人工对照源码确认。
