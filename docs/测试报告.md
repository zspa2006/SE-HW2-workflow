## 1. 环境与结果

本地环境为 Windows、CPython 3.12.8。项目声明支持 Python 3.10+，本次实际测试使用 3.12.8，未声称已经逐版本验证。

执行命令：

```powershell
python -m unittest discover -s tests -v
```

**总计 42 项：41 项通过，1 项跳过，0 项失败。** 本次测试耗时约 6.3 秒。完整逐项记录见 [测试原始输出](测试原始输出.txt)。

唯一跳过项为 `test_symlink_escape_rejected`：当前 Windows 会话没有创建符号链接的权限。相对路径越界和目录外绝对路径拒绝测试均已通过；不能因此将符号链接场景也标记为已经实测通过。测试代码保留，启用相应权限的环境中可运行。

## 3. 三类实际演示

通过 `python scripts/demo.py` 生成演示，统一输入 `examples/shop/pricing.py` 和 `orders.py`。清单见 [summary.json](evidence/summary.json)。

| 场景 | 结果 | 节点数 | 返修次数 | 证据入口 |
| --- | --- | --- | --- | --- |
| 正常流程 | succeeded | 3 | 0 | [正常报告](evidence/normal/report.html) |
| 显式漏章与返修 | succeeded | 5 | 1 | [返修报告](evidence/revision/report.html) |
| 分析后暂停，再恢复 | succeeded | 累计 3 | 0 | [恢复报告](evidence/recovery/report.html) |

返修第一次审校的真实问题是“缺少章节：验证建议”，见 `evidence/revision/step-003.json`。最终覆盖 5 个公开定义：`total_price`、`shipping_fee`、`Order`、`Order.payable`、`summarize`，最终审校通过。这里的 5 个包含类本身，不等于 5 个函数。

恢复场景在暂停时为 `status=paused/current=write/steps=1`，恢复后只运行 write 和 review。`events.jsonl` 中分析节点的开始事件仅出现一次。

## 4. 模型验证边界

所有自动模型测试使用本地 HTTP 服务，返回已知 JSON 以验证真实网络请求与节点间数据流。此方式验证接口代码行为，不验证某一云端模型的推理质量。

未配置或使用真实付费模型账号，未进行外部模型实连，不报告云端成功率、Token 费用或语义准确率。离线演示完全不访问网络。模型模式的实际效果取决于用户账号、模型能力及服务商参数兼容性。

## 5. 仍需人工判断的部分

- 源码 docstring、模型解释和业务规则是否正确，不能只凭结构测试得出结论。
- 当前版本只对明确选定的 Python 文件做静态分析，不验证动态接口和运行环境。
- 测试覆盖节点级暂停与恢复，不构成对断电、磁盘损坏或分布式故障的完整保证。
- 报告已在浏览器查看，能显示中文、消息表与文档。演示视频为实际执行产物的字幕讲解，不是实时录屏。
